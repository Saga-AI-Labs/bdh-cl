## 3. `.venv` rebuild

```bash
cd /srv/coding/bdh-cl
python3 -m venv .venv                       # system python 3.12.3
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install \
  --index-url https://download.pytorch.org/whl/cu130 "torch==2.14.1+cu130"
.venv/bin/python -m pip install numpy requests pyarrow "huggingface_hub[cli]"
```

Result: torch 2.14.1+cu130 (CUDA 13.0), triton 3.8.0, numpy 2.5.5, pyarrow
26.0.1, requests 2.34.2, huggingface_hub 2.4.0. `.venv` is 7.6 G.

**The wheel choice matters.** Do not take the plain-PyPI/cu128 torch on this box.

| build | arch list | 100M bench, b8/t512 | bf16 8192^3 matmul |
|---|---|---|---|
| old Spark reference | - | 2,192 ms/step, 1,868 B/s | - |
| torch 2.10.0+cu128 | `sm_80/90/100/120` | 3,565 ms/step, 1,149 B/s | 10.3 TFLOPS |
| **torch 2.14.1+cu130** | `sm_80/90/100/110/120` | **2,273 ms/step, 1,802 B/s** | **85.5 TFLOPS** |

Neither build lists `sm_121`, but the cu130 build runs at the expected rate
(within 4 % of the old Spark) and emits no capability warning; the cu128 build
warns and falls back. Bench is `scripts/bench_100m.py --layers 6 --steps 30`,
same param count (100,925,440) and peak (23.1 GiB) in both cases.

**Consequence for key-2:** the generation rate is back to the registered
1.39 B/s order (~6.8 h for 133 x 256 B), not the ~0.85 B/s / ~11 h the cu128
build would have cost. Replace both with the observed rate once generation runs.

`requirements.txt` still says `torch>=2.3`; a fresh `pip install -r` on this box
silently produces the slow build. Pinning the cu130 index in `requirements.txt`
is recommended but **not done** - it needs operator sign-off.
