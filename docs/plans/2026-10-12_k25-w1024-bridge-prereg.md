# K25/W1024 Bridge — Scaling Probe at Double Width

**Status:** DRAFT v0.1 · drafted 2026-10-12 · Quinn
**Purpose:** Isolate whether the BDH mechanism (storage exact, serving degraded, routing repaired) holds at `n_embd=1024` (`n_head=16`) with the same K25 territory mix.
**Hardware:** New DGX Spark with 4 TB NVMe (single host)
**Stromabschaltung:** 2026-10-14 — all devices must be powered down by then; this bridge is a post-shutdown run

---

## Why This Bridge

The K20/W512 ladder (2× multi-seed) established:
- K3 routing: 99.14–99.18% PASS
- K4 retention: PASS (median ratio 1.0000, max 1.0429)
- Joint/routed gap: 6.76–6.86×
- P5 bit-exact preservation: 25/25 phases PASS

All at `n_embd=512`, `n_head=8`, `head_dim=64`.

**Open question:** Does the mechanism survive when the base architecture is wider? This is a **pure scaling probe** — same territories, same data windows, same protocol, same instrument suite. The only changed variable is `n_embd` (512→1024, `n_head` 8→16, `head_dim` unchanged at 64).

## Instrument Suite

Per phase:

1. **Acquisition exit** — best val PPL per phase (teacher-forced)
2. **P5 in-chain** — bit-exact preservation check at every transition
3. **Own-width routdiag** — routing diagnostic at each phase-end checkpoint
4. **Retention** — routed own-width vs. acquisition exit, deltas reported
5. **Joint-vs-routed** — every phase-end checkpoint (serving confounder separated)

Final:
- 25×25 confusion matrix (200 crops/domain, window 128)
- Domain-wise retention table (all 25 territories)
- Joint/routed gap per domain
- Per-phase GPU-seconds and checkpoint bytes (cost telemetry)

## Gates

### Gate W-PASS (bridge works)
- **P5:** 24/24 transitions bit-exact (absolute stop-gate)
- **Final routing:** ≥95% own-route accuracy
- **First prose retention:** |ΔPPL| ≤ 0.08
- **Cost:** each phase ≤1.5× its projected cost; no superlinear cost curve over 24 positions
- **Resume:** a phase-boundary resume reproduces bit-identical continuation

### Gate W-PARTIAL
- P5 holds, but routing or cost degrades → PoC scope adjusted (smaller width, larger growth quanta, or capped ladder)

### Gate W-FAIL
- P5 fails → mechanism does not scale; F-V9/masking at greater depth must be re-audited before any PoC

|---|---:|---:|

| `last.pt` (bf16) | ~552 MB | ~13.8 GB |

| **Total (cumulative best+last)** | **~1.7 GB** | **~41.3 GB** |

**4 TB NVMe: comfortable.** Even with 2× headroom for logs, routdiags, and intermediate artifacts, the bridge uses <100 GB.

### GPU Memory

- W1024 model: ~46M parameters
- bf16 weights: ~92 MB
- AdamW state: ~184 MB
- Activations + KV cache for 1024-wide, 128-window: <2 GB
- **Total: <3 GB** — trivially fits on GB10 (128 GB unified memory)

### Wall-Clock Estimate

| Host | W512 per phase | W1024 per phase | 25 phases |
|---|---:|---:|---:|
| K20 (.50/.51) | ~6 h | — | — |
| Bridge (new DGX Spark) | — | ~24 h | **~600 h ≈ 25 days** |

**Assumption:** W1024 costs ~4× W512 per step (2× width, same head_dim, same sequence length). This is an estimate — the first phase's cost telemetry will calibrate it.

**Resumability:** The bridge is resumable at phase boundaries. If the run is interrupted (power event, hardware issue), it resumes from the last completed phase with F-V9 restore. Each phase's checkpoint is independently usable.

## Pre-registered Predictions

- **P-W1 (P5 size-neutral):** P5 stays bit-exact on all 24 transitions at W1024. Expected PASS since F-V9 is structural, but this is the load-bearing gate.
- **P-W2 (routing at width):** Final routing accuracy ≥95%. Falsifier: <95% → the +32/head quantum is width-bound; PoC needs larger growth steps or smaller width.
- **P-W3 (retention at width):** First prose retention |ΔPPL| ≤ 0.08. Falsifier: >0.08 → accumulated drift is width-sensitive; PoC needs periodic re-anchor steps.
- **P-W4 (cost sub-quadratically):** Per-phase GPU-seconds grow sub-quadratically with K; no superlinear rise over 24 positions. Falsifier: superlinear → PoC re-planned with grouped growth or wider blocks.
