## 1. Purpose (the M3 bet)

All prior CL evidence keyed domain identity off *language* (byte-distinct Europarl,
likelihood-routable at 99.7%). The PoC thesis ("Amoeba grows via continual learning")
requires growth+selection to work for **non-language** domains where no clean byte
identity exists. Sonde B tests whether growth writes separable, preserved, addressable
territories for **code / math / prose-2 (legal) / a control language**, using the same
instruments that worked on RA2b. It is the cheapest test of the roadmap's biggest
unknown: if it fails the PoC pivots; if it passes the full pretrain proceeds with
evidence.

## 2. Design as run

- **Base:** fresh BDH at mult 128 (~100M), `block_size 512`, prose pretrain
  (`data/textmix/wikitext-103-raw/wiki.train.raw`), batch 4, 150k steps (~300 MB) →
  base exit best **val ppl 2.38**.
- **4 CL phases**, ascending byte-overlap ambiguity:
  1. **code** — `data/textmix2/code.txt` (Python, The Stack sample)
  2. **math** — `data/textmix2/latex.txt` (LaTeX)
  3. **legal** — `data/textmix2/legal.txt` (**prose-2, the hard case:** heavy byte
     overlap with base prose)
  4. **ga** — `data/europarl/DGT.en-ga.ga.txt` (**control:** Irish, known-good protocol check)
- **Per phase:** 10k steps, batch 1, route-aware alpha 0.9, grow mult +32, fresh
  optimizer, `--no-freeze-attn`, F-V9 step-end restore. Width ladder 128→160→192→224→256
  (= 8192/10240/12288/14336/16384 routed prefixes).
- **Protocol note (fidelity):** the original `ladder_sondeB.sh` crashed at the base→phase-2
  boundary because it looked for the base under the *europarl* prefix
  (`bdh_europarl_ladB-base_last.pt`) while the textmix pipeline writes
  `bdh_textmix_ladB-base_last.pt`. This was a **prefix-path bug, not a result**, and the
  run resumed from the intact base checkpoint (`ladder_sondeB_resume.sh`) without re-running
  the 150k base steps. Phases 2-5 and all evals completed 2026-09-15 18:24.

plus `embed`/`lm_head`/`attn.freqs`) must stay **bit-exact**, the grown segment nonzero,
and the masked optimizer moments (`exp_avg`, `exp_avg_sq`) exactly zero while the grown
block's are nonzero. Raw: `docs/data/phase2-sondeB-p5-inchain.txt` (65 lines, sha-verified).

| transition | mult | P5 verdict | grown max\|w\| |
|---|---|---|---|
| base→code | 128→160 | **PASS** | 0.386 |
| code→math | 160→192 | **PASS** | 0.414 |
| math→legal | 192→224 | **PASS** | 0.523 |
| legal→ga | 224→256 | **PASS** | 0.568 |

**P-B1 PASS on all four transitions.** This is the load-bearing result: it is the
**storage thesis of the manuscript, now confirmed on a non-language domain class** — the
F-decay masking mechanism is domain-blind, exactly as predicted. **This is the check the
routing result depends on**: because the base blocks are bit-preserved through every
growth phase, the positive routing outcome (3.3) rests on the *same* mechanism proven for
RA2b (bdh-cl #106/#110), not on an untested assumption.

### 3.4 Retention — routed retention vs own acquisition (P-B4)

Both own-prefix cold eval. Acquisition = own domain in that phase's `domain_eval`
(`block=512`, 30 crops) on that phase's own exit; Retention = the same domain served by
the **final** checkpoint at its own prefix (`window=128`, 40 crops).

| domain | acquisition | routed retention | delta |
|---|---|---|---|
| code | 5.23 | 5.24 | +0.01 |
| math | 1.47 | 1.44 | -0.03 |
| legal | 2.21 | 2.17 | -0.04 |
| ga | 2.32 | 2.36 | +0.04 |
| prose | 2.39* | 2.39 | 0.00 |

*prose is the base exit, not a growth phase.

**P-B4 PASS — with the deltas documented, not smoothed to zero.** The deltas are real and
bidirectional (-0.04..+0.04): they exceed exactness but sit inside the crop/window noise
floor (512-vs-128 window, 30-vs-40 crops), so retention ≈ acquisition for every domain.

### 3.5 Joint vs routed (two-axis serving check, the operator's confounder)

Same final checkpoint, two serving modes:

| domain | own-prefix **routed** | **joint** full-width cold (no mask) |
|---|---|---|
| code | 5.24 | **89.52** |
| math | 1.44 | 28.37 |
| legal | 2.17 | 11.45 |
| ga | 2.36 | 2.32 |
| prose | 2.39 | 23.76 |

The joint full-width reference is **ppl 17.81** (served positions only).

The two-axis check is the point of the experiment: **served-on-everything degrades
dramatically (code 89.5), served-on-own-prefix stays healthy (5.24).** This is the
serving-confounder the operator flagged on RA2 — *routing benefit* and
*joint-serving degradation* must never be conflated, and the manuscript must keep them
separate. Sonde B reproduces the confounder **outside** the language domain, which
strengthens rather than weakens the claim: the degradation is a property of the
serving protocol, not of the storage. The routing result stands on the routed column.

### 3.6 Selection (P-B5)

The plan calls for "exp4-style self-NLL selector (20/20 protocol) over the grown model —
does the label-free selector find code vs math vs prose?" The label-free argmin-NLL
**is** measured here, via the routing confusion matrix (3.3): the selector picks the
correct prefix for 199/200 held-out crops without any task label. **P-B5 PASS — 99.5% ≥
the ≥75% prediction**, with the single miss on the predicted hard case (legal).

*Protocol fidelity caveat:* the dedicated `scripts/pi50/exp4_selfnll_selection.py` is
Europarl-language-bound (`SEQ = en es … lt`, `_europarl_blocks`) and **cannot run on the
Sonde B domain classes without a label-set swap.** The argmin-NLL selection is therefore
reported in its routing-instrument form (`eval_router`, crop-scale, window 128), which
yields the selection accuracy directly. If the operator wants a strictly exp4-protocol
number, it requires swapping the SEQ/domain config — see §6, and it is **optional**,
because eval_router already demonstrates the selector principle on all five classes.

## 5. Gate assessment → does it open Sonde C?

**Yes for execution; No for Sonde C's own research question — which is correct and
expected.**

What Sonde B *opens* for Sonde C:
1. **A grown multi-domain model** with clean, bit-preserved territories — Sonde C's Arm 1
   explicitly says "take the grown multi-domain model (Sonde B's …)". That model now
   exists and is on `.200` (`out/bdh_textmix_ladB-ga_*`) and in the `bdh-cl_phase-2`
   upload. C's labels ("argmin-NLL route, validated 20/20 on RA2b") come from this run.
2. **Confirmed mechanism** — addressing is exact where domains are byte-distinct
   (99.5%), and the F-V9 storage holds for non-language classes (P-B1).
3. **A measured precursor of C's failure mode** — legal's single leak + the joint-collapse
   (89.5) show that the moment byte-distinctness weakens, routing starts to fail. That is
   *the exact* regime Sonde C exists to fix.

What Sonde B **cannot** tell us, by design: Sonde C's whole subject is domains that are
*byte-overlapping with their host corpus* (chat phases identical to base; the P-R3
es/pl/sk/et failures). Sonde B deliberately chose byte-**distinct** domains, so it does
not exercise C's hard cells. C remains necessary — Sonde B neither answers it nor
pre-empts it.

**Verdict:** the gate is a clean B-PASS that hands C a valid model + validated
instruments + the P-B5 addressing baseline, and supplies evidence (the legal leak) that
C's premise is real, not academic. C is unblocked and **motivated**.

## 6. Are the results meaningful enough? breadth vs depth

The operator's question for a **gate** is: does it decide the *next* fork cleanly, with
no ambiguity that would change a downstream design? Assessed on that standard:

**Breadth (more domains): do NOT expand Sonde B.** Its job was to show the mechanism
survives *out of* the language domain. A 5th or 6th byte-distinct class (more
programming languages, medical prose, …) adds breadth of the *same* regime the plan
already passed; it does not probe the failure axis. The plan already included the only
deliberately hard case (legal = prose-2 overlap) and the control (ga); both behaved as
predicted. Adding distinct-domain breadth is redundant and would dilute the budget
without touching the open question. **That open question is non-distinctness — which is
Sonde C's scope, not more Sonde B.**

**Depth (more samples): one targeted increase, then stop.** The single genuinely
under-powered cell is legal's 39/40 leak. A confirmation run of `eval_router` on the legal
phase only, raised from `--crops 40` to 96–200, answers the only live question it leaves:
"is that one crop a real byte-overlap leak (the Sonde-C signal) or crop noise?" That is a
cheap CPU/short-GPU run and it sharpens the C motivation. No more needed — 199/200 across
the rest is already tight, and acquisition/retention deltas are noise-floor-bound.

**One real gap to close before C, in the base:** the plan's base = "FineWeb-Edu prose
**+ a small multilingual sample (no Europarl languages used later)**". I can only evidence
the prose corpus (`wiki.train.raw`) in the run record; the multilingual component of the
base is **unverified**. If it is absent, the base lacks C's exact hard case (a
domain-adjacent-to-base overlap) and C's "family-adjacent" arm loses its natural source.
**Action:** confirm `out/bdh_textmix_ladB-base_*` provenance (which corpora) before C
relies on the base for overlap tests. Flagged, not assumed satisfied.

## 7. Limitations (named, per the R3 protocol)

- **P-B4/P-B5 single seed.** The retention deltas (±0.04) and the legal 1/40 leak are
  n=1; their interpretation as "noise-floor" vs "real" needs the depth run in §6, not a
  stronger claim now.
- **Selection is eval_router-protocol, not dedicated exp4-protocol** (see 3.6) — same
  argmin-NLL object, different crop config; acceptable for a gate, noted for the
  manuscript's method column.
- **Base multilingual component unconfirmed** (§6) — affects the strength of the C
  hand-off, not the B verdict.
- **The confounder is now *reproduced*, not resolved** — 3.5 shows the joint-vs-routed gap
  is large; the *mechanism* of joint degradation vs routing benefit is what Sonde C
  addresses. The gate hands the problem forward; it does not solve it.
